1. 什么是 Hook，为什么用？

Hook（钩子） = Claude Code 在自己的生命周期里预留的「事件挂载点」。 你写个脚本注册到某个事件，它就会在该事件发生时被自动调用。

本项目实例：
我们想让 Claude 在你打 prompt 时把内容推到手机飞书。Claude Code 自己不知道飞书的存在， 但它提供了 UserPromptSubmit 事件。我们注册一个 Python 脚本到这个事件， Claude 每收一条 prompt 就调用我们脚本 → 脚本 HTTP POST 给本地 bridge → bridge 发飞书。 全程 Claude 本体没改一行代码。

常见用途：

  • 🛡️ 安全门禁：在 PreToolUse 拦截 rm -rf
  • 📊 审计日志：把每次 Bash 命令写进日志文件
  • 🎨 自动格式化：在 PostToolUse 文件编辑后自动跑 Prettier
  • 📱 外部通知：长任务完成时推送到手机 / Slack / 邮件（本项目）
  • 🧠 会话开场注入上下文：SessionStart 时把当前 git 状态喂给 Claude
  • 📐 规则强制：Stop 时检查是否所有测试都跑过，没跑就让它接着干

2. 工作原理：一图看懂

┌────────────┐ ┌──────────────┐ │ Claude TUI │ ── 1. 事件发生 (如 UserPromptSubmit) ──▶│ Claude 主进程 │ └────────────┘ └──────┬───────┘ │ 2. 读 settings.json，按 matcher 筛出要跑的 hook │ ▼ ┌────────────────────────────────┐ │ spawn 子进程：python post_hook.py│ │ │ │ stdin ← JSON {prompt, cwd…} │ │ stdout/stderr → Claude 读 │ │ exit code → Claude 看 │ └────────────────────────────────┘ │ 3. 根据 exit code + stdout，决定是否继续/阻止/注入上下文

关键点：

  1. Hook 进程独立于 Claude。你可以写 Python / Bash / Node / 任何能读 stdin 的程序。
  2. 每次事件触发就 spawn 一次新进程，不是常驻服务。
  3. Claude 给你 JSON 事件数据，你给 Claude 退出码 + 可选 JSON 决策。
  4. Hook 在 Claude 等待期间同步运行（除非标 async: true），所以别做太重的活。

3. 配置文件 settings.json

三个位置，优先级从低到高

位置作用域典型用途
~/.claude/settings.json你所有项目个人偏好，跨项目通用工具
<项目>/.claude/settings.json本项目，入 git团队共享的项目规则
<项目>/.claude/settings.local.json本项目，不入 git个人本地覆盖
本项目选了第二种。E:\MyProject\RC\.claude\settings.json 入 git，团队任何人 clone 后启用 hooks 都生效。

基本结构

{
  "hooks": {
    "<事件名>": [
      {
        "matcher": "<可选过滤模式>",
        "hooks": [
          {
            "type": "command",
            "command": "python $CLAUDE_PROJECT_DIR/hooks/post_hook.py user_prompt"
          }
        ]
      }
    ]
  }
}

本项目真实配置

{
  "hooks": {
    "UserPromptSubmit": [
      { "matcher": "", "hooks": [{ "type": "command",
          "command": "python $CLAUDE_PROJECT_DIR/hooks/post_hook.py user_prompt" }] }
    ],
    "Stop": [
      { "matcher": "", "hooks": [{ "type": "command",
          "command": "python $CLAUDE_PROJECT_DIR/hooks/post_hook.py stop" }] }
    ],
    "PreToolUse": [
      { "matcher": "", "hooks": [{ "type": "command",
          "command": "python $CLAUDE_PROJECT_DIR/hooks/post_hook.py pre_tool" }] }
    ]
  }
}
注意：改了 settings.json 后不会热加载，需要退出 Claude 再重启会话。 /hooks 命令可以看当前生效的 hook 列表。

4. Hook 的 5 种 type

① command（最常用）— spawn 一个进程

{
  "type": "command",
  "command": "python my_script.py",
  "timeout": 30,              // 秒，默认 600（UserPromptSubmit 默认 30）
  "shell": "bash"             // 可选；Windows 默认 Git Bash
}

本项目就用这个。command 字符串走 shell，$CLAUDE_PROJECT_DIR 等占位符自动展开。

② command 的 exec 形式（避 shell 解析）

{
  "type": "command",
  "command": "node",
  "args": ["${CLAUDE_PROJECT_DIR}/script.js", "--fix"]
}

带 args 数组就走 execFile()，不经过 shell，特殊字符不用转义。 Windows 上跑 .cmd / .bat 推荐这个。

③ http — POST 到 HTTP 端点

{
  "type": "http",
  "url": "http://localhost:8080/hook",
  "headers": { "Authorization": "Bearer $TOKEN" },
  "allowedEnvVars": ["TOKEN"]       // 只有列出来的环境变量会被插值
}

响应 2xx 视为成功，可以返回 JSON 决策字段。本项目其实可以用这个直接替代 command + post_hook.py，让 hook 直接 POST 给 bridge —— 少一层 python 进程。 我们当初选 command 是为了能在 hook 里做本地预处理。

④ mcp_tool — 调一个已连接的 MCP 工具

{
  "type": "mcp_tool",
  "server": "my_server",
  "tool": "security_scan",
  "input": { "file_path": "${tool_input.file_path}" }
}

⑤ prompt — 让一个小 LLM 判断

{
  "type": "prompt",
  "prompt": "检查是否所有测试都通过。若否，返回 {\"ok\": false, \"reason\": \"...\"}",
  "model": "claude-haiku-4-5-20251001"
}

用 Haiku 跑一个轻量 LLM 评估。也有 agent 类型，能调工具（实验中）。

5. 核心 6 个事件详解

29 个事件挑最常用的 6 个详讲。其余在下一节列表。

① UserPromptSubmit — 用户按 Enter 提交 prompt

同步阻塞 可阻止 无 matcher · 默认 30s 超时

触发时机

用户在 TUI 里输完一段 prompt 按 Enter，Claude 还没看到内容之前。 你可以拦截这条 prompt（exit 2 拒绝），或在 stdout 输出补充上下文。

stdin 里有啥

{
  "session_id": "abc-123",
  "transcript_path": "C:/Users/.../session.jsonl",
  "cwd": "E:\\MyProject\\RC",
  "hook_event_name": "UserPromptSubmit",
  "prompt": "用户打的那段话",
  "permission_mode": "auto"
}

本项目用法

# hooks/post_hook.py（节选）
elif hook_type == "user_prompt":
    text = (data.get("prompt") or "").strip()
    if text:
        post(BRIDGE_BASE + "/hook/user_prompt", prefix + text)

读出 prompt 文本，POST 给本地 bridge，bridge 把它推送到手机飞书显示「🧑 [项目] 你打的话」。

② Stop — Claude 一轮回复完成

同步阻塞 可阻止（让 Claude 接着说） 无 matcher · 默认 600s 超时

触发时机

Claude 这一轮（包括工具调用 + 最终回复）全部结束，准备让用户输入下一句之前。 你可以让它别停——exit 2 让 Claude 继续干活（典型：测试还没跑就别停）。

stdin 里有啥

{
  "session_id": "abc-123",
  "transcript_path": "C:/Users/.../session.jsonl",
  "cwd": "E:\\MyProject\\RC",
  "hook_event_name": "Stop",
  "stop_hook_active": false,         // 之前是否已让 Claude 继续过
  "last_assistant_message": "..."    // 最后一条 assistant 消息
}

本项目用法

elif hook_type == "stop":
    tp = data.get("transcript_path") or ""
    text, out_tokens, dur_ms = extract_stop_summary(Path(tp))
    if text:
        badge = f"({dur_ms/1000:.1f}s · {out_tokens} tok)"
        post(BRIDGE_BASE + "/hook/assistant_reply", f"{prefix}{badge}\n{text}")

我们顺着 transcript_path 翻 JSONL，提取最后一条 assistant message + 这一轮 duration + token 数，推手机看「🤖 [RC] (15.2s · 1137 tok) 回复正文」。

坑：Stop hook 连续 block 8 次后 Claude Code 强制忽略。 看到 stdin 里 stop_hook_active=true 就该退出，不要无限 block。

③ PreToolUse — Claude 准备调工具

同步阻塞 可阻止 / 可改入参 matcher: 工具名（Bash / Edit / Read / 自定义 MCP）

触发时机

Claude 决定要调一个工具（如 Bash 跑命令），还没真的调之前。 最强大的 hook —— 能拦截、能改入参、能加上下文。

stdin 里有啥

{
  ...
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_use_id": "tool_xxx",
  "tool_input": {
    "command": "rm -rf /",
    "description": "..."
  }
}

例 1：本项目—— 把工具调用推手机

elif hook_type == "pre_tool":
    tool_name = data.get("tool_name") or "?"
    summary = summarize_tool(tool_name, data.get("tool_input") or {})
    post(BRIDGE_BASE + "/hook/tool_use", f"{prefix}{tool_name}: {summary}")

实时把「🛠️ [RC] Bash: ls /etc」之类推到手机，让远程用户能跟踪 Claude 在干什么。

例 2：拦截 rm -rf

# .claude/hooks/block-destructive.sh
#!/bin/bash
INPUT=$(cat)
CMD=$(echo "$INPUT" | jq -r '.tool_input.command')
if echo "$CMD" | grep -q 'rm -rf'; then
  jq -n '{
    hookSpecificOutput: {
      hookEventName: "PreToolUse",
      permissionDecision: "deny",
      permissionDecisionReason: "rm -rf 被禁止"
    }
  }'
fi
exit 0

④ PostToolUse — 工具调用完成（成功）

同步阻塞 可让 Claude 重做 matcher: 工具名

触发时机

工具调完且成功返回。工具已经执行了，你阻止不了发生，但能把信息塞回 Claude 让它「不要走下一步」或「按这个结果重新想」。

典型用法：自动格式化

{
  "PostToolUse": [{
    "matcher": "Edit|Write",
    "hooks": [{
      "type": "command",
      "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
    }]
  }]
}

Claude 一改 .ts 文件，自动跑 prettier。它感知不到，但磁盘上代码已经格式化好了。

姊妹事件：PostToolUseFailure

工具调用失败时触发，stdin 里有 tool_error 字段。可以做错误自愈、重试策略。

⑤ SessionStart — 会话开始

非阻塞 仅注入上下文 matcher: source (startup / resume / clear / compact)

触发时机

新会话开始、/resume、/clear、自动 /compact 等四种情况都会触发。可以用 matcher 区分。

典型用法：开场注入 git 状态

{
  "SessionStart": [{
    "hooks": [{
      "type": "command",
      "command": "echo \"当前分支: $(git branch --show-current)\\n最近 3 个 commit:\\n$(git log --oneline -3)\""
    }]
  }]
}

每次开会话，Claude 自动「看到」你的 git 状态，不用你再手动告诉它。

压缩之后注入提醒

{
  "SessionStart": [{
    "matcher": "compact",
    "hooks": [{ "type": "command",
      "command": "echo '提醒：用 bun 而不是 npm；commit 前跑 bun test'" }]
  }]
}

⑥ Notification — Claude 主动通知用户

非阻塞 仅观察 matcher: type (permission_prompt / idle_prompt / auth_success / ...)

触发时机

Claude 弹权限对话框、idle 提醒、登录成功等场景。可以挂个 hook 让它响个铃 / 推 Slack。

例：idle 时桌面通知

{
  "Notification": [{
    "matcher": "idle_prompt",
    "hooks": [{ "type": "command",
      "command": "osascript -e 'display notification \"Claude 在等你\"'" }]
  }]
}

7. 输入/输出协议

输入：stdin 拿 JSON

每次 hook 触发，Claude spawn 你的进程，把事件 JSON 写到 stdin。 所有事件共享这些字段：

字段含义
session_id会话 ID
transcript_path本会话 JSONL 文件绝对路径（可用于翻历史）
cwd事件发生时 Claude 的工作目录
hook_event_name事件名（如 "PreToolUse"）
permission_mode当前权限模式

事件特定字段见上面各事件详解。

输出：退出码 + stdout

exit含义行为
0成功解析 stdout 为 JSON 决策；动作继续
2阻止忽略 JSON，把 stderr 当错误反馈给 Claude，阻止动作（仅特定事件能被阻止）
其他非阻塞错误stderr 第一行展示，动作继续

JSON 决策字段（exit 0 时有效）

{
  "continue": false,                  // 整个会话停掉
  "stopReason": "构建失败",
  "suppressOutput": false,            // 隐藏本 hook 的 stdout
  "systemMessage": "警告",            // 给用户显示一行警告

  // 事件特定：
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow|deny|ask",
    "permissionDecisionReason": "...",
    "updatedInput": { "command": "改写过的命令" },
    "additionalContext": "塞给 Claude 的额外上下文"
  }
}

8. Matcher 语法

模式含义例子
"" / "*" / 省略匹配所有每次都触发
纯字母数字 + |精确匹配 / OR 列表Bash、Edit|Write
含其他字符JavaScript 正则^Notebook、mcp__.*__write.*
FileChanged 例外：它的 matcher 不是正则，是字面文件名，按 | 切。

额外过滤：if 字段（v2.1.85+）

{
  "matcher": "Bash",
  "hooks": [{
    "type": "command",
    "if": "Bash(git *)",                  // 只当命令匹配 git * 时才触发
    "command": "./check-git-policy.sh"
  }]
}

9. 路径占位符

在 command 字段里这几个占位符会被自动展开：

占位符含义
$CLAUDE_PROJECT_DIR项目根目录（有 .claude/ 的地方）
$CLAUDE_PLUGIN_ROOT插件安装目录
$CLAUDE_PLUGIN_DATA插件持久化数据目录
$CLAUDE_ENV_FILE会话级环境变量文件（读写都行）
本项目就是用 $CLAUDE_PROJECT_DIR 解决了一个真实 bug： 之前 hook 命令写相对路径 python hooks/post_hook.py，Claude 给 Bash 工具 cd 到子目录后，相对路径就找不到了。改用 $CLAUDE_PROJECT_DIR/hooks/... 就无论 cwd 在哪都对了。

10. 调试技巧

/hooks 命令

在 Claude TUI 里输 /hooks，会弹出浏览器列表，显示当前生效的所有 hook （事件名、matcher、来源文件、command）。哪个 hook 没生效，看一眼就知道。

开启 debug 日志

claude --debug-file /tmp/claude.log
# 或在会话内
/debug

自己加日志（本项目做法）

# post_hook.py
LOG_PATH = Path(__file__).resolve().parent / "post_hook.log"

def log(line):
    with LOG_PATH.open("a", encoding="utf-8") as f:
        f.write(f"{datetime.now().isoformat()} {line}\n")

每次 hook 跑都追加一行到本地 log 文件。出问题就 tail 一下。

11. 常见踩坑 15 条

  1. settings.json 不热加载 —— 改完要重启 Claude 会话才生效。
  2. matcher 区分大小写 —— Bash ≠ bash。
  3. FileChanged 的 matcher 不是正则，是字面文件名。
  4. 相对路径会被 Claude 的 cwd 改变破坏。用 $CLAUDE_PROJECT_DIR 或绝对路径。
  5. Git Bash 加载 ~/.bashrc 会污染 stdin/stdout，导致 JSON 解析失败。 Profile 里的 echo 要包 if [[ $- == *i* ]]。
  6. exit code 2 不是所有事件都能阻止 —— SessionStart/Notification 等忽略 exit 2 只显示 stderr。
  7. Stop hook 连续 block 8 次后被强制忽略，看 stop_hook_active 决定退出。
  8. 多 hook 修改同一个 tool_input，顺序不确定 —— 别这么设计。
  9. hook 是同步阻塞（除非 async: true），别在 PreToolUse 里跑 30 秒任务。
  10. PermissionRequest 在 -p 非交互模式下不触发，要改用 PreToolUse。
  11. async hook 的 stdout / exit 都被忽略，只能做副作用（日志/通知），不能阻止动作。
  12. HTTP hook 的 header 环境变量插值，只有 allowedEnvVars 列出来的会展开，防泄漏。
  13. PreToolUse 的 allow 不能绕开权限规则，只能收紧不能放开。
  14. stdin 默认按系统 codepage 解码（中文 Windows 是 GBK），中文 prompt 会乱码。 用 sys.stdin.buffer.read() 自己按 UTF-8 解。
  15. 同一事件内多 hook 并行跑，结果合并最严格的赢（deny > ask > allow）。
记一个最重要的 mental model： hook 是 Claude 的"事件流"中插一根管子。 你拿到 JSON，决定要不要让事件继续、要不要改它、要不要给 Claude 加点提示。 本质上你在做 middleware。
