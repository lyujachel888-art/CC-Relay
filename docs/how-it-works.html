🌉 cc-feishu-bridge 是怎么工作的

简单说：让你在 手机飞书 和 电脑 Claude Code 终端 之间双向通讯 ——你打的字会出现在手机上，手机回的话会让 Claude 接着干活。

三个角色，住在哪

名字住处干嘛的
bridge WSL1 Linux（Python） 中枢。一头接飞书 API，一头接 wrapper
wrapper Windows（Python + ConPTY） 把 Claude TUI 包在一个伪终端里，留个 socket 让 bridge 注字符进去
Claude Windows 原生 claude.exe 就是 Claude Code 本体，不知道自己被包了
飞书 云端 + 你的手机 消息进出口

路径 ①：你在终端打字 → 手机收到推送（出站）

这条路径 不需要 wrapper。任何 Claude Code 会话只要项目根有 .claude/settings.json（注册了 hooks）就自动生效。

你在终端打 "看看 README"  ↵
   ↓
Claude 触发 UserPromptSubmit hook
   ↓
   hook 是 .claude/settings.json 里配的一行：
       python hooks/post_hook.py user_prompt
   ↓
post_hook.py 读 stdin 拿到 prompt
   ↓ HTTP POST  /hook/user_prompt
bridge server.py 收到
   ↓ 调 lark_oapi
飞书 API
   ↓
🔔 你的手机：🧑 [RC] 看看 README

——————— Claude 回复完后 ———————

Claude 触发 Stop hook
   ↓
post_hook.py 翻 transcript.jsonl，找最后一条 assistant message
   + 拿 turn_duration 和 output_tokens
   ↓ HTTP POST  /hook/assistant_reply
bridge
   ↓

              这是 Claude 的回复内容...

同理，每次 Claude 调工具（Bash / Edit / Read…）也会触发 PreToolUse hook：

🔔 🛠️ [RC] Bash: ls /etc
🔔 🛠️ [RC] Edit: src/main.py

路径 ②：你在手机打字 → 终端 Claude 响应（入站）

这条路径 必须有 wrapper。原因：要把消息送进 Claude 的 stdin，但 原生 claude.exe 的 stdin 是它自己的 ConPTY，外部进程没法直接写。

解决：用 wrapper.py 启动 Claude，它在中间架一个 ConPTY，留一个 TCP socket （127.0.0.1:8788）让 bridge 把字符塞进去。

你的手机 → 飞书 → 飞书云
                    ↓ WebSocket 长连接
bridge long_conn.py handler 收到 "你好"
                    ↓
              echo_filter.mark_injected("你好")
                    ↓ 这一步是为了等会儿 hook 回来时不要再 🧑 推一遍
              injector.inject("你好")
                    ↓ TCP send to 127.0.0.1:8788
wrapper socket_to_pty 线程收到
                    ↓ proc.write("你好") + 80ms + proc.write("\r")
              ConPTY 把字节流交给 Claude（用 UTF-8 codepage 解码）
                    ↓
Claude TUI 看到输入 + Enter，把它当 prompt 提交
                    ↓
              再走 路径 ① 那一套 → hook → 飞书
                    ↓
              但这一次：bridge 在 /hook/user_prompt 发现
              "[RC] 你好" 去掉前缀后 = 刚才 mark 过的 "你好"
                    ↓
              ✋ 跳过 🧑 推送（避免你看到自己刚发的话）

最后手机只看到：
   🛠️ [RC] (Claude 调的工具)
   🤖 [RC] (Xs · Y tok) 你好！有什么我可以帮你的吗？

编码踩坑：为什么 wrapper 启动 Claude 那么复杂

中文 Windows 控制台默认 codepage 是 936（GBK）。 wrapper 写 UTF-8 字节给 ConPTY，ConPTY 用 GBK 解码 → Claude 看到乱码。 所以 wrapper 用 cmd /c "chcp 65001 && claude.exe" 启动 —— 让 chcp 65001 先把子进程控制台切到 UTF-8，再启动 Claude。

同样，hook 端的 Python 默认按 GBK 读 stdin，Claude 写来的 UTF-8 JSON 会被解错。所以 post_hook.py 用 sys.stdin.buffer.read() 读 原始字节，自己按 UTF-8 解码。

🆕 透明化 shim：模式开关

正常你输 claude 启动的是原生 claude.exe（只能出站，不能入站）。 启动 wrapper 需要敲长长一串 .\scripts\launch_claude_wrapper.ps1，麻烦。

方案：在你的 PowerShell $PROFILE 里塞一个 claude function，按环境变量决定走哪条路：

命令结果
$env:CLAUDE_BRIDGE = '1'; claude → 走 wrapper，支持双向飞书
$env:CLAUDE_BRIDGE = '0'; claude → 走原生 claude.exe（只出站，不入站）
Enable-ClaudeBridge 然后 claude 同上，开
Disable-ClaudeBridge 然后 claude 同上，关
关键点：开关是 每个 PowerShell 窗口独立 的。 你可以一边开个普通窗口写代码（不被飞书干扰），一边另开一个窗口 Enable-ClaudeBridge 用手机远程。

怎么装

& "E:\MyProject\RC\scripts\install-claude-shim.ps1"

装完关掉当前 PowerShell，开新的窗口就能用 Enable-ClaudeBridge。 脚本只往 $PROFILE 加 5 行（带可识别标记），重复跑不会重复加。

启动顺序总结

  1. WSL1：跑 bash scripts/launch_bridge.sh（一次跑着就行，长连 + HTTP 都在里面）
  2. Windows PowerShell：开一个普通窗口
  3. 在里面：Enable-ClaudeBridge; claude
  4. 手机就能聊了
